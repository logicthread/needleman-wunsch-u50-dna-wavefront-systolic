## Reproduce the local checks (no FPGA tools)

```bash
git clone https://github.com/Xilinx/HLS_arbitrary_Precision_Types third_party/HLS_arbitrary_Precision_Types
export AP_INT_INC=$PWD/third_party/HLS_arbitrary_Precision_Types/include
make test
```

`make test` runs: the on-card traceback walker against the host walker and the CPU DP
optimum (13 cases).

## Build for hardware (needs Vitis 2025.1, XRT, a U50)

```bash
cp scripts/env.sh scripts/env.local.sh      # edit XILINX_ROOT / XRT_SETUP; export LM_LICENSE_FILE
source scripts/env.sh
make sw_emu PE=512        # small array; UNTESTED, see Known gaps
make hw_emu PE=512        # UNTESTED
make hw                   # 3968 PE; ~5 h route; UNTESTED from this repo
make bench XCLBIN=build/hw/nw_tile_u50.xclbin
```

## Known gaps in the commands above

1. The `v++` lines in the Makefile were transcribed from `linear/scripts/link.sbatch` (the
   script that built the earlier 3968-PE builds) and from the S1t notes. The macro list of
   the S1t `v++ -c` is **confirmed** (checked in Step 2): the command line recorded in the
   build's `nw_tile_u50.xo.compile_summary` is `-D NW_PE=3968 -D WV_TILE_PE=128
   -D WV_TRACEBACK -D WV_DIR_B3 -D WV_SEAM_RELAY -D WV_QDEPTH=65536 -D WV_RDEPTH=65536
   -D WV_BDEPTH=1048576 -D WV_DIRDEPTH=8388608 --kernel_frequency 300`, identical to the
   `Makefile` `DEFS`. The link-step options (pre-route hook for the floorplan) are in
   `linear/cfg/`; the link was *not* reproduced from this repository.
2. The shipped S1t bitstream was not produced by one clean `v++` run: routing finished
   but write_bitstream hit the 6 h Slurm limit, and the xclbin was recovered with
   `v++ --reuse_impl` (NOTES N81, N82). A fresh `make hw` therefore needs a longer wall-time
   limit and has never been run end-to-end in this form.
3. `sw_emu` support for the `hls::task`-based kernel is **UNKNOWN** (the kernel was only
   ever checked with Vitis HLS csim/cosim and on silicon).
4. Real-card runs in the measured campaign went through a course service with rate limits;
   running the host directly on a local U50 is expected to work (the host uses plain XRT)
   but was not done by the author of these notes.
